## 1. 등고선 — **통합안 확정**

평균 면적에 대응하는 단일 임계선이 없다는 지적은 맞다. 그래서 **역방향으로 푼다.**

```
전체 좌표로 밀도면을 만든다  (기존과 동일)
  ↓
표준화 면적(N=60 · R=20 평균)을 목표값으로 잡는다
  ↓
밀도 내림차순으로 셀을 쌓아 그 면적이 되는 지점의 임계값을 찾는다
  ↓
그 임계값으로 등고선을 그린다
```

**실측 검증 완료 (Claude Code, 표본 12명):** 재구성 등고선 면적이 표준화 값과 **최대 오차 0.24%p**로 일치한다. 등고선이 담는 활동 질량은 50% → **평균 44.6%**로 바뀐다.

- 화면의 숫자와 그림이 **같은 양**이 된다. CCA 값을 두 종류 두지 않는다.
- 등고선 모양은 전체 좌표로 그리므로 한 번 뽑기의 노이즈를 타지 않는다.
- **정의가 바뀌므로 provenance에 명시한다:** `formulaVersion: "fixed-n60-r20-v2"`, 표준화 면적, 등고선이 담는 실제 질량 비율, 유효 좌표 수, `lowSample`.
- V1 `app.py`가 `continuous_core` 를 import 하므로 **시그니처 변경 시 V1 동반 확인 필수.**

## 2. 전술 요약 3번째 줄 — **두 축으로 교체 (확정)**

### 왜 바꾸는가 (실측 근거)

`cca_area_pct` 는 "활동 반경"을 재지 않는다. 실측 상관:

```
CCA vs 좌우 퍼짐(y 표준편차)  r = +0.573
CCA vs 전후 퍼짐(x 표준편차)  r = -0.079   ← 사실상 무관
```

즉 **좌우 점유만 보고 전후 이동은 못 본다.** 결과적으로 축구 상식과 반대되는 라벨이 나온다:

| 포지션 | CCA | 전후 퍼짐 | 좌우 퍼짐 |
|---|---|---|---|
| Right Midfielder | **10.5%** (최하위권) | **24.7** (전체 1위) | 18.0 |
| Right Back | 11.8% | 23.7 (2위) | 13.8 (최하위) |
| Central Midfielder | **18.5%** (상위) | 18.7 (하위) | 23.7 |

터치라인을 가장 많이 오르내리는 풀백이 "좁은 활동 반경형"으로, 좌우로만 흔들리는 중미가 "넓은 활동 반경형"으로 찍힌다.

### 새 산출

세 번째 줄을 **두 축**으로 바꾼다. 각 축은 기존 4조각 규칙(**값 → 기준선 → 차이 → 백분위**)을 그대로 따른다.

| 축 | 정의 |
|---|---|
| **전후 활동폭** | 활동 좌표 x의 표준편차 |
| **좌우 활동폭** | 활동 좌표 y의 표준편차 |

- 기준선은 **동일 시즌 · 동일 모드 · 동일 스코프 · 동일 포지션** 코호트의 중앙값. **scope 3/5/7을 8로 몰래 바꾸지 않는다.**
- 라벨은 **백분위에서 파생**한다 (상위 20% 이내 → 넓은 범위형 / 하위 20% → 좁은 범위형 / 그 외 → 동포지션 평균권). 하드코딩 절대 임계값 금지 — 죽은 분류가 원리적으로 생기지 않게 한다.
- 두 축 조합으로 **종합 역할 라벨**을 만든다:

```
전후 넓음 + 좌우 넓음  →  전방위 활동형 (박스투박스)
전후 넓음 + 좌우 좁음  →  종적 왕복형 (터치라인/채널 침투)
전후 좁음 + 좌우 넓음  →  횡적 조율형 (좌우 전환)
전후 좁음 + 좌우 좁음  →  고정 위치형
```

### 참조 실측값 (이 숫자로 레이아웃을 잡을 것)

### ⚠️ 문구 제약 (반드시 지킬 것)

- 표준편차는 **활동 "범위"**이지 **이동 "거리"가 아니다.** 총 이동거리는 트래킹 데이터가 있어야 산출되며 우리에겐 없다.
- 따라서 **"많이 뛴다" "활동량이 많다" 류의 문구를 쓰지 마라.** 정확히 말할 수 있는 것은 **"같은 포지션 선수들보다 넓은 범위에 걸쳐 활동한다"** 뿐이다.
- 이는 `오프 더 볼` 명칭을 폐기한 것과 동일한 원칙이다 — 데이터가 못 주는 것을 이름이나 문구로 약속하지 않는다.
- 중앙값 미만인 값에 "상위 65%"라고 표기하면 읽기 어색하다. 표기 규칙을 정해 일관되게 적용할 것(예: 중앙값 미만은 "하위 N%").

# 6. 재현성 규칙 (2026-08-26 확정, 실측 검증됨)

`A` 구현 전 반드시 이대로 고정한다. 셋 다 재실행 결과에 영향을 준다.

## 6-1. 난수 seed — **선수별 결정적 파생** (전역 순차 금지)

기준 seed는 `20260826` 이지만, **그 값을 그대로 전역 RNG에 쓰면 안 된다.** 선수를 순회하며 하나의 RNG를 공유하면 앞 선수가 난수를 소비한 만큼 뒤 선수의 표본이 달라져, **처리 순서·대상 범위·병렬화에 따라 값이 바뀐다.**

실측 (같은 선수, 처리 순서만 다르게):
```
전역 순차 seed  →  9.2045  vs  9.2259   (차이 0.0213%p)
선수별 결정적    →  9.1264  vs  9.1264   (차이 0.0000%p)
```

**확정 규칙:**
```python
BASE_SEED = 20260826
per_player_seed = int(hashlib.sha256(f"{BASE_SEED}:{heatmap_key}".encode()).hexdigest()[:16], 16)
rng = random.Random(per_player_seed)
# 이 rng 로 R=20회 rng.sample(points, 60) 를 수행하고 coreAreaPct 를 평균낸다
```

- 키는 반드시 **`heatmap_key`** 를 쓴다 (선수·대회·시즌을 모두 식별하는 값).
- 이렇게 하면 **한 명만 재계산해도 전체를 재계산해도 같은 값**이 나오고, 병렬 처리도 안전하다.
- `numpy.random` 이 아니라 **Python 표준 `random.Random`** 을 쓴다. 구현이 갈리면 값이 달라진다.

## 6-2. 역산 임계값 — 후보 전수 탐색

```
후보 = unique(density[density > 0])
각 후보 t 에 대해  area(t) = mean(density >= t) * 100
|area(t) − 표준화면적| 이 최소인 t 를 선택
동률이면 더 큰 t 를 선택 (= 더 작은 면적. 과대평가보다 과소평가가 안전하다)
```

실측 근거 (표본 40명):

| 방식 | 오차 중앙값 | 오차 최대 |
|---|---|---|
| 단순 K번째 값 | 0.067%p | **0.440%p** |
| 후보 전수 탐색 | 0.067%p | **0.270%p** |

두 방식의 개별 선수 면적 차이는 최대 **0.710%p** 까지 벌어진다. 배포 게이트가 ±0.5%p 이므로 **단순 방식은 최대치가 게이트에 걸릴 수 있다. 전수 탐색으로 간다.**

## 6-3. 동밀도 셀 처리 — 기존 관례 재사용

동일 밀도 셀은 **전부 포함**한다. 실측상 **65%의 선수에서 동밀도 tie가 발생**하므로 코너 케이스가 아니다.

마스크 산출은 **`continuous_core.py` 에 이미 있는 형태를 그대로 쓴다:**

```python
core_mask = density >= threshold - np.finfo(float).eps * max(1.0, peak)
```

기존 코드의 주석이 밝힌 의도(대칭 고밀도 섬에서 좌/우 임의 편향 방지)와 동일하다. **새로 만들지 말고 재사용해야** 기존 경로와 새 경로가 미세하게 어긋나지 않는다.

# 7. 발행값 정정 (2026-08-26 확정) — 게이트 충돌 해소

## 문제

`A` 구현 중 전수 검증에서 등고선 면적 오차가 ±0.5%p 를 넘는 행이 발견됐다 (최대 0.6108%p, `179515:34:61736`).

## 원인 — 알고리즘 오류가 아니라 격자 양자화

704칸 격자에서 면적의 최소 단위는 `100/704 = 0.1420%p` 다. 그러나 동밀도 셀이 뭉쳐 있으면 임계값을 한 단계 내릴 때 면적이 여러 칸씩 점프한다.

실패 행 정밀 분석:
```
1030212:23:76457   목표 17.5497%  달성 17.0455%  오차 0.5043%p (3.5칸)
  달성 가능한 후보들의 오차: 0.5043 → 0.6321 → 0.9304 → 1.0582
  → 목표에 더 가까운 면적이 존재하지 않는다

179515:34:61736    목표 15.8097%  달성 15.1989%  오차 0.6108%p (4.3칸)
```

빈도는 낮다. 표본 300명 기준 오차 중앙값 0.0568%p, p90 0.1776, p99 0.2912, 최대 0.4119 — **±0.5%p 초과 0건**. 10,412행 전체에서 소수만 걸린다.

## 확정 — **등고선이 실제로 그린 면적을 발행한다**

게이트를 완화하지 않는다. 표준화 목표값이 아니라 **달성 면적(등고선의 실제 면적)** 을 `cca_area_pct` 로 발행한다.

```
표준화 목표값 (N=60·R=20 평균)   →  내부 중간값. provenance 에만 노출
달성 면적 (등고선의 실제 면적)     →  cca_area_pct 로 발행. 화면 표시값
```

그러면 **숫자와 그림의 오차가 정의상 0** 이 된다.

### 근거 — 통계적 성질이 보존된다

```
표준화 목표값 vs log(저장 좌표수)   r = +0.523
달성 면적값   vs log(저장 좌표수)   r = +0.525     ← 동일
두 값의 상호 상관                  r = +0.9994    ← 사실상 같은 값
```

표본 편향 보정 효과가 그대로 유지된다. 목표값은 중간 계산물이며, 사용자가 읽는 값은 "그려진 영역의 면적"이어야 한다.

### 왜 게이트 완화가 아닌가

게이트를 ±0.65%p 로 완화하면 **"그림은 17.05%인데 숫자는 17.55%"인 상태를 허용**하는 것이다. 그것은 통합안을 고른 이유 자체를 부정한다. 통합안의 목적은 화면에 CCA 값이 두 종류 존재하지 않게 하는 것이었다.

## 게이트 재정의

| | 이전 | 확정 |
|---|---|---|
| 등고선 면적 vs 발행값 | ±0.5%p 이내 | **정의상 0. 불일치 시 구현 오류** |
| 발행값 vs 표준화 목표값 | — | **보고만 한다(차단하지 않음).** 최대 오차와 해당 키를 리포트에 남긴다. 참고 상한 1.0%p(≈7칸) |

## provenance 필수 필드

```
formulaVersion      "fixed-n60-r20-v2"
ccaAreaPct          달성 면적 (= 등고선 면적 = 표시값)
standardizedTarget  표준화 목표값 (중간값)
quantizationDelta   |달성 − 목표|
containedMassPct    등고선이 담는 활동 질량 비율 (약 44.6% 부근)
validPointCount     유효 좌표 수
lowSample           좌표 60개 미만 여부
```

```
activity_spread_y   활동 좌표 y 의 표준편차 (좌우 활동폭)
```

- 요청 시점에 히트맵 좌표에서 계산하지 말 것. **ETL 에서 미리 산출**한다.
- 계산 비용은 CCA 와 비교해 무시할 수준이다(재추출 20회가 없고 단순 표준편차 2개). A 의 CSV 재생성보다 훨씬 가볍다.
- **정규화 좌표(0~100) 그대로 계산한다.** 미터 변환은 하지 않는다 — 헥스 차트와 달리 여기서는 동일 축끼리만 비교하므로 단위 일관성만 있으면 된다. 다만 **x 와 y 를 서로 비교하지 말 것**(척도가 다르다). 각 축은 자기 코호트 기준선과만 비교한다.
- 유효 좌표 60개 미만 행에도 값을 산출하되 `low_sample` 로 표기한다.

## 8-2. 코호트 정의와 저표본 실태

코호트 = **시즌 × 스코프(8대리그/유럽대항전) × 포지션**. 스코프 3/5/7 을 8 로 몰래 바꾸지 않는다.

실측 (유효 좌표 60개 이상):

```
총 코호트 156개 · 크기 중앙값 20명 · 최대 303명
  20명 이상 코호트  79개 (50.6%)
  선수-행 기준      6,967/7,499 (92.9%) 이 20명 이상 코호트에 속함
```

**코호트의 절반이 20명 미만이지만, 선수 행 기준으로는 93%가 안전하다.** 큰 코호트에 인원이 몰려 있기 때문이다. 실무적으로 **약 7%의 선수가 `low_sample` 표기를 보게 된다.**

계약 요구:
- 코호트 인원 20명 미만 → `low_sample: true`. 값은 그대로 제공하되 화면에서 표시한다
- **값을 숨기거나 전체 평균으로 몰래 대체하지 않는다**
- 응답에 `cohortPopulation`, `cohortKey`(시즌·스코프·포지션)를 반드시 포함한다
- 포지션 정규화는 기존 `_benchmark_position_key` 재사용. 역할 의미를 병합하지 않는다

## 8-3. 인수 테스트 기준값 — 이 숫자를 정확히 재현해야 한다

구현 후 아래를 그대로 재현하는지 확인하고 보고한다. 어긋나면 코호트 정의나 표준편차 산출이 스펙과 다른 것이다.

```
Harry Kane · Striker · 8대리그 · 2025/2026 · N=303
  전후 활동폭  22.645   기준 18.119   +4.526   상위  2.0%
  좌우 활동폭  21.308   기준 22.913   -1.605   하위 35.0%

Jens Toornstra · Defensive Midfielder · 8대리그 · 2023/2024 · N=138
  전후 활동폭  20.851   기준 18.766   +2.085   상위 11.6%
  좌우 활동폭  26.611   기준 23.866   +2.744   상위 15.9%
```

- 기준선은 **코호트 중앙값**이다(평균 아님).
- 백분위 표기: 중앙값 이상이면 `상위 N%`, 미만이면 `하위 N%`. Kane 의 좌우축이 후자의 예다.
- 참고: Toornstra 는 A 에서 최대 점수 변동(−1.57)이 발생한 선수다. 두 축 판독에서는 **양쪽 모두 평균 이상(전방위 활동형)** 으로 나오며, 이는 그의 활동이 넓고 옅게 퍼져 기존 CCA 가 부풀어 있었다는 A 의 진단과 일치한다. 단일 CCA 수치가 놓치던 정보를 두 축이 복원한 사례다.

## 8-4. B 계약에 반드시 포함할 필드

```
formulaVersion       산식 버전
cohortKey            시즌 · 스코프 · 포지션
cohortPopulation     코호트 인원
lowSample            20명 미만 여부
value / baseline / delta / percentile   각 축마다
roleLabel            2×2 조합 라벨 (전방위 활동형 / 종적 왕복형 / 횡적 조율형 / 고정 위치형)
```

라벨은 **백분위에서 파생**한다. 하드코딩 절대 임계값을 쓰지 않는다 — 죽은 분류가 생기지 않아야 한다.

**문구 제약 재확인:** "많이 뛴다", "활동량" 류 표현 금지. 표준편차는 범위이지 이동거리가 아니다. 화면 고지 문구는 `활동 폭은 위치 분포의 범위이며 이동 거리가 아닙니다.`

# 9. §8-3 인수 테스트 기준값 정정 (2026-08-27)

## 9-1. §8-3 의 참조값은 폐기한다

§8-3 에 적힌 `Kane N303 / 18.119 / 22.913`, `Toornstra N138`, `Lewis-Potter N20` 은 **틀렸다.**

작성자(Claude Code)가 **스코프를 무시하고 국내 리그를 전부 뭉쳐서** 코호트를 만들었다. §8-2 에 "스코프 3/5/7 을 8 로 몰래 바꾸지 않는다" 고 적어놓고 참조값은 그 규칙을 어긴 채로 산출했다.

실측 확인 (2025/2026 · Striker):
```
국내 리그 전부            325행
8대리그 (Belgian 포함)     325행
7대리그 (Belgian 제외)     287행    ← scope 7 의 올바른 모집단
좌표 60개 이상 (잘못된 필터) 303행    ← §8-3 이 쓴 값
```

스코프 정의는 `app.py:2192` 기준: **7대 = 8대 − Belgian Pro League**.

## 9-2. 구현이 옳다

`_v2_frame` 을 exact 하게 유지하고 참조 문서에 맞추려 행을 합성하거나 scope/global fallback 으로 보정하지 **않은 것이 옳은 판단**이다. 문서가 틀렸을 때 데이터를 문서에 맞추면 계약이 무너진다.

교차 검증 (Claude Code, scope 7 프레임 재계산):
```
                    Claude Code    구현
N                       287        284
전후 활동폭 중앙값     18.0831    18.2692
좌우 활동폭 중앙값     22.2680    22.8373
Kane 본인 전후/좌우   22.6447 / 21.3076   (일치)
```

**선수 개인 값은 일치**하므로 표준편차 산출 로직은 동일하다. 차이는 코호트 구성원 3행뿐이다.

## 9-3. 남은 확인 사항 — 코호트 적격성 필터

구현이 `NaN CCA / 정적 세션 부재` 행을 제외해 287 → 284 가 됐다. **이 필터의 정확한 정의를 계약 문서에 명시해야 한다.**

특히 확인할 것:

> **활동폭 축의 코호트를 CCA 유효성으로 거르고 있지는 않은가?**

`activity_spread_x/y` 와 `cca_area_pct` 는 서로 다른 지표다. CCA 를 계산할 수 없는 행이라도 활동폭은 산출 가능할 수 있다. **CCA 결측을 이유로 활동폭 코호트에서 빼면 무관한 사유로 모집단이 줄어든다.**

요구:
- 코호트 적격성은 **지표별로** 판정한다. 활동폭 축은 활동폭 유효성으로, CCA 축은 CCA 유효성으로 판정한다
- 제외 사유를 계약 응답의 provenance 에 노출한다 (`cohortPopulation` 과 함께 제외 건수/사유)
- 제외 규칙을 API_CONTRACT.md 에 문장으로 명시한다

## 9-4. 새 인수 기준

**참조값을 문서에 고정하지 않는다.** 스코프별로 달라지고 데이터 스냅샷에 따라 움직이므로, 고정 숫자를 문서에 박으면 이번과 같은 불일치가 반복된다.

대신 아래 **불변 조건**으로 검증한다:

1. Kane(2025/2026 · Striker · scope 7)의 **전후 활동폭은 22.64 ± 0.01**, **좌우 활동폭은 21.31 ± 0.01** 이다. 이는 코호트와 무관한 선수 개인 값이므로 스냅샷이 바뀌어도 유지된다
2. Kane 의 **전후 축은 상위권(중앙값 초과), 좌우 축은 중앙값 미만** 이다 → 역할 라벨 **종적 왕복형**
3. 같은 선수를 **scope 7 과 scope 8 로 조회하면 코호트 인원과 백분위가 달라야 한다.** 같으면 스코프가 무시되고 있다는 뜻이다 — 이것이 가장 중요한 회귀 검사다
4. 코호트 인원 20명 미만이면 `low_sample: true` 이고 값은 보존된다

# 10. 화면 상태 규정 (프론트 착수용, 2026-08-27)

Figma `21:2` 는 **정상 상태만** 그려져 있다. 아래 상태는 시각 참조가 없으므로 이 문서를 정본으로 구현한다. Figma 트랙이 진행되면 이 규정에 맞춰 시안을 추가한다.

## 10-1. ⚠️ `low_sample` 사유는 두 가지다 — 같은 배지로 뭉개지 말 것

기준 분리(§9-3, 2026-08-27) 이후 저표본 사유가 둘로 갈렸다. **원인이 다르므로 문구도 달라야 한다.**

| 사유 | 조건 | 의미 | 문구 |
|---|---|---|---|
| `low_sample_cohort` | 코호트 인원 < 20 | 비교 대상이 부족하다. **선수 값은 정상** | `비교 대상 N명 — 기준선 해석에 주의하세요` |
| `insufficient_valid_coordinates` | 본인 유효 좌표 < 60 | **선수 값 자체가 측정 부족**. 기준선은 정상 | `측정 표본 부족 (좌표 N개) — 값 해석에 주의하세요` |

- 두 사유가 동시에 성립할 수 있다. 그때는 **둘 다 표시**한다.
- 색은 `color/data/amber`.
- **값을 숨기거나 회색 처리하지 않는다.** 관측된 값은 그대로 보여주고 주의만 표시한다.
- 좌표 부족 행은 **기준선 계산에서 제외**되지만 **자기 값은 계속 표시**된다. 이 두 규칙을 혼동하지 말 것.

## 10-2. `unavailable` — 기준선을 만들 수 없는 경우

포지션이 `Coach` 이거나 유효한 선수 역할이 아닌 경우. **전체 평균으로 대체하지 않는다.**

```
비교 기준 없음 · 선수 역할 정보 없음
```

선수 본인 값(활동폭·박스 안 활동 등)은 산출 가능하면 그대로 표시하고, **기준선·차이·백분위 세 조각만 비운다.** 빈 자리는 `—` 로 표기하고 이유를 캡션에 남긴다.

## 10-3. 코호트 문구 — 스코프별 변형

카드 상단 코호트 라인은 **실제 조회 컨텍스트를 그대로** 적는다. 8대리그로 뭉뚱그리지 않는다.

```
비교 기준 · 7대리그 · Striker · N=284 · 서버 산출
비교 기준 · 유럽대항전 · Attacking Midfielder · N=237 · 서버 산출
비교 기준 · 3대리그 · Center Back · N=41 · 서버 산출
```

스코프 라벨: `3대리그 / 5대리그 / 7대리그 / 8대리그 / 유럽대항전`.
**유럽대항전과 국내 리그의 기준선을 절대 섞지 않는다** (좌표 수를 맞춰도 유럽이 전 포지션 약 5%p 낮다 — 대회 구조 차이).

## 10-4. 로딩

섹션 1 카드 형태를 유지한 스켈레톤. 3개 지표 블록 각각에 대해 라벨·값·막대·캡션 자리를 회색 블록으로 표시한다. `motion-reduce` 를 존중한다(기존 관례).

## 10-5. 오류

```
전술 요약을 불러오지 못했습니다.        [다시 시도]
```

- 재시도 버튼은 최소 44px 터치 영역.
- 카드 자체는 유지하고 내부만 오류 상태로 바꾼다. 카드가 통째로 사라지면 레이아웃이 흔들린다.

## 10-6. 표기 규칙 재확인 (구현 시 자주 틀리는 것)

| 항목 | 규칙 |
|---|---|
| 중앙값 **이상** | `상위 N%` · `color/accent/primary` · 막대는 평균 눈금 **오른쪽** |
| 중앙값 **미만** | `하위 N%` · `color/data/rose` · 막대는 평균 눈금 **왼쪽** |
| 막대 스케일 | **백분위 0~100 트랙**, 중앙 50에 `평균` 눈금, 초과분만 채움 |
| 소수점 | 활동폭·CCA는 소수 1자리, 비율은 정수 |
| 고지 문구 | `활동 폭은 위치 분포의 범위이며 이동 거리가 아닙니다.` (활동 범위 블록 하단, 고정) |

**세 요소(문구·색·막대 방향)가 항상 일치해야 한다.** 하나라도 어긋나면 사용자가 반대로 읽는다.

## 10-7. 하지 말 것

- 백분위를 hover 뒤에 숨기기 (터치 기기에서 접근 불가)
- `low_sample` 두 사유를 하나의 배지로 합치기
- 기준선 없음을 전체 평균으로 대체하기
- 내부 상태값(`low_sample`, `unavailable`, `insufficient_valid_coordinates`)을 화면에 영문 그대로 노출하기
- 브라우저에서 중앙값·백분위 재계산 — 서버 응답을 렌더링만 한다

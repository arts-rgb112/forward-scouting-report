# 작업지시서 — 기동 시 캐시 예열 (B)

발주자 승인 완료 2026-09-04. 담당: Codex(행정). 검수: Claude(사법).

## 왜 (실측 근거)

인스턴스는 `1c-2g`(2GiB/1CPU)로 상향 완료. 메모리는 더 이상 문제가 아니다 — 컨텍스트 9개를
전부 태우고도 241MB / 2,147MB = **11.2%**. 남은 문제는 **콜드캐시 하나**다.

같은 페이지, 같은 요청 9개를 두 번 던진 실측:

| | 콜드(재시작 직후) | 웜(2회차) |
|---|---|---|
| 시즌 레일 8건 | **전부 504** (8초 서버 데드라인 초과) | 226~666 ms |
| 상세 1건 | **141,226 ms** | 246 ms |
| 페이지 전체 | **141.23 s** | **0.67 s** |

`autoDeploy: yes`(commit, main)이고 실측 배포 빈도가 **하루 약 4.8회** — 하루 5번쯤 캐시가 날아가고
그 직후 첫 방문자가 141초와 504를 맞는다. 콜드메일 링크를 받은 사람이 그 방문자일 수 있다.

## 요구사항

1. `api_server/main.py` 에 기동 훅을 추가해 캐시를 예열한다.
2. **포트 개방을 막지 마라.** 예열은 백그라운드 태스크로 던지고 훅은 즉시 반환한다.
   기동이 늦어지면 Render 배포가 실패하거나 롤백된다.
3. **예열은 순차로.** 1 CPU 다. 병렬로 돌리면 경합만 만든다 — 실측에서 9개 병렬 시
   CPU 가 0.99/1.0 로 포화되고 페이지가 141초 걸렸다.
4. 예열 대상은 **시즌 레일이 때리는 캐시**다: `supported_seasons()` × `("league","europe")` 조합에 대한
   `_v2_player_summary_index(season, mode, scope, competition)`.
   scope·competition 은 프론트가 실제로 보내는 기본값을 **코드에서 확인해서** 맞춰라
   (프로덕션 로그 관측치는 `scope=8, competition=all` 이었다). 추측하지 말고 확인해라.
5. **동기 함수는 반드시 `run_in_threadpool` 로 호출해라.** `async` 컨텍스트에서 직접 호출하면
   방금 커밋 `fa65ede` 로 고친 이벤트 루프 블로킹 버그가 그대로 재발한다.
   **이 티켓에서 가장 중요한 제약이다.**
6. 예열 실패는 삼킨다. 예열이 깨져도 서비스 기동은 성공해야 한다. 실패는 로그만 남긴다.
7. 환경변수로 끌 수 있게 한다(기본 on). 예: `API_WARM_CACHE=0` 이면 건너뛴다.
8. 컨텍스트 하나 끝날 때마다 소요 ms 를 로거로 남긴다. Render 로그에서 예열 진행이 보여야 한다.

## 금지

- `lru_cache` 의 `maxsize` 변경 금지 — 별건이다.
- Render 설정·인스턴스 타입 변경 금지.
- 새 라이브러리 추가 금지. 기존 `run_in_threadpool` / `asyncio` 로 해결된다.
- 점수 산식·코호트 계산 로직에 손대지 마라. 이 티켓은 **호출 시점**만 바꾸는 것이다.

## 완료 조건 — 아래를 증거로 제출해야 판정한다

1. `git diff`
2. 기동 훅이 **즉시 반환**하는 것을 보인 로그(기동 완료 시각 vs 예열 완료 시각이 분리돼 있어야 함)
3. `python -m pytest tests/test_api.py tests/test_shotmap_contract.py -q` 출력
   — `tests/test_player_summary_latency.py` 의 실패 2건은 `origin/main` 에서도 동일하게 나는
   기존 실패다. 회귀로 계상하지 않는다.
4. 커밋 SHA / 브랜치 / push 여부

브랜치는 새로 판다. push·merge·배포는 발주자 승인 사안이다 — 커밋까지만 하고 SHA 를 보고해라.

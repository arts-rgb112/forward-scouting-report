## P0-2 개정 (2026-09-04 확정) — 3D 를 워크스페이스 밖 전용 라우트로 분리

**아래 원안(탭별 레이어 분리)은 절반만 유효하다.** 원안 표는 탭을 *질문*으로 적어놨는데 실제 탭은
*렌더 방식*(2D 회랑 / 3D 회랑)이라, 구현하면 3D 탭이 마커·궤적을 강제로 숨기게 된다 — 오늘 완료·
스크린샷 검증한 3D 도트매트릭스 마커(`0844fa0`)가 화면에서 사라지고, `CODEX_3D_VISUAL_QA_PROTOCOL.md`
§2-3 의 `QuadraticBezierCurve3` 궤적 요구사항도 렌더할 대상이 없어진다. 스펙끼리의 충돌이었다.

**확정 구조:**
```
선수 상세 (메인)     2D 회랑(슈팅: 마커·궤적) + 골대맵 + 전술분석 요약
                     그 아래: 히트맵 / 레이더 / 스탯보드  ← 움직임 데이터는 여기로 내려감
                     └ [3D로 보기] 링크 → 새 탭
/player/:id/3d      3D 회랑 전체화면 (자유시점 카메라 · 마커 · 궤적 · 히트맵)
```

- **3D 탭을 워크스페이스에서 제거**하고 전용 라우트로 옮긴다. 메인 페이지에서 WebGL 청크(638KB)와
  GLB(14.5MB)가 아예 안 실리는 게 핵심 목적이다.
- **`window.open()` 금지, 진짜 라우트로 만든다.** 팝업은 앱을 새로 부팅해서 데이터를 다시 받고
  (느린 엔드포인트를 한 번 더 겪는다), 뒤로가기·북마크가 깨진다. 라우트로 하면 URL 이 공유 가능해져
  구단·에이전시에 링크 하나로 보낼 수 있다. 기존 URL 파라미터 보존 로직(`preserveExternalQuery`)을 재사용해라.
- 3D 는 좁은 패널이 아니라 전체화면을 쓴다 — 자유시점 카메라와 마커가 그래야 제 값을 한다.
- 워크스페이스에 남는 탭의 레이어 분리(2D 회랑 = 슈팅 전용)는 원안대로 유지한다. 이미 구현됐다.

**주의 — 이 개정이 성능 문제 전체를 푸는 게 아니다.** 응답 16.6초(최악 35.1초)는 프론트 번들이 아니라
Render 백엔드 콜드스타트다. 3D 분리는 첫 화면 무게만 해결한다. 백엔드 지연은 캐싱·웜 유지로 별건 처리.

# 탭 구조 확정 (발주자 결정 — P0-2 의 표를 이것으로 대체한다)

탭은 **4개**, 라벨은 짧은 서술형으로 간다. 질문형 긴 라벨은 폐기한다.
(`어디서 쏘고 어디로 꽂나` → `2D 회랑` 등)

```
2D 회랑 | 3D 회랑 | 히트맵 | 골대맵
```

| 탭 | 노출 | 숨김 | 근거 시안 |
|---|---|---|---|
| **2D 회랑** | 6레인 회랑, 레인별 슛/득점/xG/활동 표, 판독문, PK 별도 표기 | 히트맵, CCA | `figma_8642` + `8651` |
| **3D 회랑** | 동일 6레인 구조를 3D 로. 궤적, 4각도 프리셋, 줌 프리셋 3종 | 히트맵은 바닥 레이어로만 최소 노출 | `figma_8378`·`8424`·`8065`·`8398`·`8440` |
| **히트맵** | 히트맵 + CCA 윤곽선 **전용** | **슈팅 마커 전부** | `figma_8304`·`9074` |

히트맵은 독립 탭이므로 슈팅 마커를 완전히 걷어낸다. 이것이 "다 몰려 있어 패턴이
안 보인다"는 지적의 구조적 해법이다.

전문 용어는 넣지 않는다. `xG` `xGOT` `/90` `CCA` 만 유지한다.

**xG 에 따라 크기를 바꾸는 방식을 2D 에서 폐기한다.** 박스 안에서 전부 겹친다.

|---|---|
| 득점 | 채운 원 · 연두 |
| 유효 슛 | 채운 원 · 파랑 |
| 빗나감 | `×` 표 |
| 블록 | 빈 원 (테두리만) |

## 6. 구역별 비율 표시 — 신규

승인 시안(3D)에는 구역 번호와 점유율이 맵 안에 찍힌다 (`16 · 16.67%`, `15 · 15.56%` 등).

- **2D 회랑:** 맵 안에 상시 표기하지 않는다. **해당 구역을 클릭하면** 관련 정보를 연다.

## A. 원인

컴포넌트마다 각자의 Figma 시안에서 따로 크기를 가져와 **공통 타입 스케일이 없다.**

```
TacticalSummaryV2             9 · 10 · 11(×7) · 13 · 26 · 30px + xs/sm/lg
SixLaneCorridorPitch          10px + text-xs(×7)
```

## B. 타입 스케일 (공통 토큰으로 정의, 컴포넌트에서 임의값 금지)

발주자 기준선: **상세 스탯 카드의 점수 배지("88") 크기가 최저선.**

| 역할 | 크기 | 용도 |
|---|---|---|
| `display` | 32px | 프로필 총점(87). **현재 56px 는 과하다** |
| `metric` | 24px | 전술 요약 대표 수치. **현재 30/26px 는 과하다** |
| `title` | 18px | 섹션 제목 |
| `body` | **16px** | 본문·지표값·표 셀. **이것이 최저선이다** |
| `label` | 14px | 라벨·단위·축 이름 |
| `caption` | 12px | 진짜 주석만. 남발 금지 |

### 규칙
1. **12px 미만 사용 금지.** 현재 `text-[8px]` `[9px]` `[10px]` `[11px]` 전부 제거한다.
2. 컴포넌트에서 `text-[Npx]` 임의값을 쓰지 않는다. 위 6개 토큰만 쓴다.
3. 피치 주변 주석(활동 좌표 개수, 구획 설명 등)도 `caption` 이상으로 올린다.
   현재 `text-xs`(12px) 이하로 깔린 설명문이 많다.
4. 전술 요약은 **줄이고**, 상세 스탯 하위 지표와 프로필 카드 수치는 **키운다.**
   지금은 정반대다.

## C. 레이아웃 — 빈 공간 제거

현재 좌우 2열에서 좌열만 길어지고 **우측이 검은 공백**으로 남는다. 반복되는 문제다.

발주자 지시:
- **프로필 그리드 오른쪽에 다른 콘텐츠를 배치한다.** 지금은 비어 있다.
- **히트맵(피치)과 전술 요약이 한 화면에 같이 보이게 한다.**
  현재 전술 요약이 피치 아래 좁은 좌열에 들어가 스크롤해야 보인다.

즉 전술 요약을 **피치 옆**으로 올려 같은 시야에 두고, 프로필 우측 공백을 없앤다.
섹션은 계속 **가로 전폭** 단위로 유지한다. 좌우 두 기둥 구조로 되돌아가지 마라.

## D. 검증

- 저장소 전역에서 `text-\[([0-9]|1[01])px\]` 매칭이 **0건**이어야 한다.
- 변경 후 스크롤 없이 피치와 전술 요약이 같이 보이는지 뷰포트 1440×900 기준으로 확인.
- 빈 공백 영역이 남는지 확인해서 보고.

# 3차 피드백 (발주자, 2026-08-30) — 7건

## 1. 상세 스탯 보드 첫 화면은 카테고리만

접힘 상태인데도 카테고리마다 세부 지표 4개가 그대로 노출된다.
**첫 화면은 6개 카테고리 이름 + 점수 + 막대까지만** 보여준다.
세부 지표는 전부 펼침 영역으로 내린다. 데이터는 삭제하지 않는다.

## 2. 레이더 폰트만 과도하게 커졌다

축 라벨(`박스 밖 슈팅` 등)이 차트를 덮어 글자끼리 겹치고 잘린다.
축 라벨은 `label`(14px) 수준으로 낮추고, 차트 안에 들어가도록 배치를 조정한다.

## 3. 폰트가 실제로는 안 바뀌었다 — 이전 검증이 무효

이전 검사(`text-\[Npx\]` 0건)는 **통과했지만 크기는 그대로였다.** 구멍이 둘이다.

```
SVG fontSize 속성 19곳:  8 · 9 · 10 · 10.5 · 11 · 12 · 13 · 15px   ← 검사 범위 밖
text-xs(12px) 58회 / text-sm(14px) 40회 / text-base(16px) 1회
   → 임의값을 캡션 크기 클래스로 바꾸기만 해서 검사를 통과
```

### 요구
- **SVG `fontSize` 속성도 타입 스케일을 따른다.** 12 미만 전면 금지.
- 본문·지표값·표 셀은 `body`(16px)를 쓴다. `text-xs`(12px)를 본문 자리에 쓰지 마라.
  현재 `text-xs` 58회는 대부분 본문 자리다.
- `caption`(12px)은 진짜 주석에만 쓴다.

### 검증 (이번엔 양쪽 다 본다)
```
1) grep -rE 'text-\[([0-9]|1[01])(px|rem)?\]' src  →  0건
2) grep -roE 'fontSize="[0-9.]+"' src | 값이 12 미만인 것  →  0건
3) grep -c 'text-base' src  →  본문 사용처 수만큼 존재할 것
4) text-xs 사용처를 전수 나열하고, 각각이 진짜 주석인지 근거를 답할 것
```
**4번을 반드시 답해라.** 숫자만 맞추고 넘어가는 것을 막기 위한 항목이다.

## 4. 2D 회랑 줌에 화면 이동(팬)이 없다

현재 확대하면 가운데로만 커지고 이동이 불가능해 쓸모가 없다.
**확대 상태에서 드래그로 이동(팬)이 되어야 한다.** 레거시 2D 와 동일하게.
경계를 벗어나지 않도록 클램프한다.

## 5. 구역 클릭 정보가 구현되지 않았다

2차 피드백 6번의 2D 부분이 미구현이다. **해당 구역을 클릭하면** 그 구역의
슈팅 분포(슛/득점/xG)와 히트맵 점유 비율이 보여야 한다.
서버 집계가 없는 값은 `—` 로 두되, **클릭 동작 자체는 동작해야 한다.**

## 6. 3D 구역 라벨이 무슨 뜻인지 알 수 없다

`22 · 0.56%` 만 찍혀 있어 판독이 불가능하다. 숫자가 구역 번호인지 무엇인지,
0.56%가 무엇의 비율인지 알 수 없다.
**마우스를 올리면(호버) 해당 구역 정보가 뜨도록 한다.**
표시 내용: 구역 이름/위치, 활동 점유율, 슛·득점·xG. 없는 값은 `—`.

## 7. 3D 회랑 페널티 박스의 중좌·중우가 분할되지 않았다

2D 회랑은 PK 축(y=50)으로 중앙 레인을 L3L·L3R 로 나눈다.
**3D 회랑의 박스 구역도 동일하게 나누고 각각의 수치를 산출한다.**
두 탭의 레인 경계는 반드시 동일해야 한다 — 같은 구조를 두 시점에서 보는 것이다.

## 공통

- 데이터가 없으면 임의로 만들지 말고 `—`. 상호작용(클릭·호버)은 데이터와 무관하게 동작할 것.
- 실데이터 시각 QA 를 못 했으면 못 했다고 보고할 것. 추정 보고 금지.

## 8. 시즌 막대 — 티어 사다리 폐기, 점수 비례로 변경 (발주자 결정 번복)

이전 §5 에서 "티어 사다리 위치로 확정, 재논의 금지" 로 기록했으나 **발주자가 번복했다.**
실제 데이터에서 케인이 5시즌 전부 Diamond 1 이라 막대 5줄이 전부 100% 로 같아졌다.
점수는 78.3~87.3 으로 9점 차인데 막대는 구분이 없다.

### 변경
- **막대 길이 = 점수 / 99.** 99 를 가득 찬 상태로 본다.
  ```
  87.3 → 88.2%    83.1 → 84.0%    82.9 → 83.7%
  80.9 → 81.7%    78.3 → 79.1%
  ```
- 색은 티어 색을 유지한다.
- `tierLadderPercent()` 는 더 이상 막대 길이에 쓰지 않는다.

### 알려진 대가 (발주자 인지함)
점수 기반 길이는 티어를 넘나들 때 역전이 생긴다 (72.4 Emerald 가 72.0 Diamond 보다 길다).
과거 이 이유로 거부된 방식이나, 색으로 티어를 구분하므로 감수한다.
**같은 티어 안에서 시즌 차이가 안 보이는 문제가 더 크다는 판단이다.**

## 9. 프로필 카드 — 크기만 키웠고 가독성이 없다

전체 폭으로 늘리면서 **라벨은 왼쪽 끝, 수치는 오른쪽 끝**에 떨어져 시선이 이동해야 한다.
막대는 화면을 가로지르는 가는 선이 되어 길이 비교가 안 된다.

### 요구
- 프로필 카드는 **원래 좁은 폭(약 300px) 기준으로 설계된 것**이다.
  전체 폭으로 늘릴 거면 **레이아웃을 다시 짜라.** 같은 배치를 늘리기만 하면 안 된다.
- 시즌 행에서 **연도·티어·점수·막대가 서로 가까이** 묶여야 한다.
  현재처럼 좌우 양끝으로 벌리지 마라.
- 폰트는 3번의 타입 스케일을 따른다. 시즌 점수는 `body`(16px) 이상.
- 전체 폭이 남으면 **행을 늘리지 말고 열을 나눠라** (예: 시즌 이력을 2열로).

## 1. 선수 요약 블록 — 전술 요약 아래 빈 공간에 배치

피치 오른쪽, 전술 요약 아래가 비어 있다. **여기에 선수 요약을 넣는다.**

### 성격
개별 지표 나열이 아니라 **한 화면의 데이터를 종합해 특징을 서술**하는 블록이다.
발주자 예시: *"케인은 대부분의 득점이 박스 우측에서 나왔다"*

이것은 `messi-specs/CODEX_TACTICAL_SUMMARY_V3_ORDER.md` **PART 2(2차 분석)**의
렌더 위치다. 새 기능이 아니라 이미 명세된 분석 계층이 표시될 자리다.

- **코호트 분위수가 필요한 패턴**은 사전계산 artefact 완료 후 붙인다.

### 규칙 (재확인)
- 모든 문장에 **근거 숫자를 함께 표기**한다.

- 최대 2개 패턴. 조건 미달이면 아무것도 쓰지 않는다.
- 표본 부족 시 발화하지 않는다.

라벨이 무엇을 뜻하는지 화면에 한 줄로 밝혀라 (예: "숫자는 슈팅 비중").

# 6차 피드백 (발주자, 2026-08-30) — 6건

## 1. 3D 골대 정면 + 박스 — 이제 구역별로 크롭돼서 나온다

검게 나오던 것은 고쳐졌으나 **반대로 과교정됐다.** 잔디가 화면을 가로지르는 띠로
잘려 나오고 위아래가 검다. **원래 방식(전체 피치가 보이는 것)이 낫다.**

- 카메라가 가깝고 낮을 때도 **잔디 폴리곤 전체가 그려져야 한다.**
- 클립 경로나 매트가 화면을 잘라내면 안 된다.
- 4개 프리셋 × 3개 줌 = 12개 조합에서 잔디가 온전히 보이는지 확인해 보고하라.

## 2. 박스 뷰에서 히트맵이 잔디와 구분되지 않는다

히트 램프의 **저밀도 구간이 올리브-초록**이라 초록 잔디 위에서 안 보인다.

**저밀도 색을 초록 계열에서 빼라.** 잔디와 색상환에서 떨어진 계열(청록·파랑 등)로
시작해 노랑 → 주황 → 빨강으로 올라가게 한다. 고밀도 구간은 유지.

라이브 스트림릿 램프를 그대로 따르던 기존 결정을 **이 항목에 한해 변경**한다.
근거: 스트림릿은 배경이 초록이 아니었다.

## 3. 3D 줌 조작이 일반적인 줌과 다르다

발주자 표현: *"일반적인 사람들이 인식하는 줌아웃 스타일이 아니라서 매우 불편"*

현재는 **카메라 거리(distance)를 움직이는 돌리(dolly)** 방식이다. 거리가 바뀌면
원근이 함께 변해 화면이 확대되는 게 아니라 **시점이 이동하는 것처럼 보인다.**

**일반적인 지도·이미지 줌처럼 동작하게 바꿔라.**
- 화면 중심(또는 커서 위치)을 기준으로 **배율이 커지는** 느낌이어야 한다
- 줌 중에 원근 왜곡이 급격히 변하지 않아야 한다
- `전체 필드 / 공격 진영 / 박스` 3개 컨트롤이 슬라이더처럼 보여 혼란스럽다.
  **프리셋 버튼임이 드러나게** 하거나, 연속 줌과 역할을 분리하라
- 구현 방식(거리 조절 유지 + 화각 보정 / 뷰포트 스케일 전환 등)은 판단해서 제안하고
  선택 근거를 보고하라

## 4. CCA 선을 더 진하게

현재 `width 1.6 / opacity 0.72`. **색감이 더 진해야 한다.**
투명도를 올리거나 색을 진하게 하되, 마커를 덮지 않는 선에서 조정하고 결과를 보고하라.

## ★ 5. 2D 회랑 마커 — 세 번째 지적이다. 접근을 바꿔라

크기 조정만으로는 세 번 실패했다. 발주자 요구: **"슈팅 마커 부피를 반토막낼 정도의 개혁"**

아래를 **전부** 적용한다. 하나씩 시도하지 마라.

1. **반지름을 현재의 절반으로.** 현재 `radius = 1.35` → `0.7` 수준
2. **테두리(stroke)를 얇게.** 테두리가 두꺼우면 실제 크기보다 커 보인다
3. **채움 투명도 0.55~0.65.** 겹쳐도 아래 마커가 비쳐야 한다
4. **흰 헤일로·링이 남아 있으면 제거한다.** 겉보기 부피를 키우는 주범이다
5. **겹침 묶음(clustering) 을 구현한다.** 4차 피드백에서 지시했으나 미구현으로 보인다.
   같은 지점에 다수가 겹치면 묶어서 개수 배지를 띄우고 클릭 시 목록을 편다

적용 후 **케인 108발이 실제로 개별 식별 가능한지** 확인해서 보고하라.
"작게 만들었다"가 아니라 "몇 발이 겹쳐 보이는지"로 답하라.

## 6. 골대맵 — 호버는 유지, 표시 방식을 원래 흰 숫자로

**상시 노출로 되돌리는 것이 아니다.** 호버 시에만 나오는 동작은 그대로 두되,
**나올 때의 렌더링을 원래 흰 숫자 방식으로** 바꾼다.

현재는 호버 시 숫자가 이상한 방식으로 그려져 **잘려서 나온다.**

- 호버(및 키보드 포커스) 트리거는 **유지**한다
- 표시되는 숫자는 **이전의 흰 숫자 스타일**을 그대로 쓴다 (`62%` / `212` 2행 구성)
- **잘림을 반드시 해결하라.** 셀 경계 안에 들어오게 배치하고, 필요하면
  셀 밖으로 나가는 대신 툴팁 형태로 띄운다
- 마커에 가리지 않도록 z 순서를 조정한다

# 7차 피드백 (발주자, 2026-08-31) — 3D 회랑 3건

## 1. 줌 프리셋 3종 제거

`전체 필드` · `공격 진영` · `박스` 컨트롤이 **아무 효과가 없다.**
6차 3번에서 휠·state 를 화면 배율로 옮기면서 프리셋이 고아가 된 것으로 보인다.

**세 컨트롤을 제거해라.** 슬라이더처럼 보여 혼란만 준다.
줌은 `−` / `+` / `초기화` 와 휠·핀치로 충분하다.

제거 전에 6차 3번(줌 방식 이전)이 완료 상태인지 먼저 확인해서 답해라.
반쯤 이전된 상태로 남아 있으면 그것부터 정리한다.

## 2. 좌측·우측을 정확히 90° 로

현재 `좌측` · `우측` 프리셋의 방위각을 **피치 길이축에 수직인 정확한 90° / 270°** 로 맞춘다.
측면에서 정면으로 보는 각도가 판독이 낫다.

고도는 현행 유지(27~30°). **고도까지 낮추면 납작해져서 안 된다.**

## ★ 3. "골대 정면" 이 활주로처럼 늘어난다 — 핫픽스

`180° · 27° · 84m` 에서 피치 전체가 원근으로 길게 늘어나 **골대가 화면 끝의 점이 되고
아무것도 판독되지 않는다.** 현재 가장 심각한 3D 문제다.

### 요구
**골대 정면에서는 상대 진영만 프레이밍한다.**

- 카메라를 골대 쪽으로 당기고, 프레임을 **공격 진영(또는 파이널 서드)로 한정**한다
- 하프라인 아래에서 나온 슛이 화면 밖으로 잘려도 **감수한다.** 발주자 명시 지시다
  (케인처럼 먼 거리 슛이 있어도 골대 정면 뷰에서는 버린다)
- 잘린 슛이 있으면 화면에 **"화면 밖 N발" 로 표기**해서 감춘 것이 아님을 밝힌다
- `골대 뒤` 프리셋도 같은 문제가 있는지 확인하고 동일하게 처리한다

### 검증
4개 프리셋 각각에서
1. 골대가 화면에서 차지하는 비율
2. 표시되는 슛 수 / 전체 슛 수
3. 판독 가능 여부 캡처

를 보고해라. 발주자가 보고 판단한다.

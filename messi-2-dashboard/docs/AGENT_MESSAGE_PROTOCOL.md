# 에이전트 간 메시지 규격 (양방향 통일)

발주자 지시 2026-09-04: *"코덱스 → 클로드 / 클로드 → 코덱스 양쪽 시스템 다 스펙 맞춰서 통일화시켜봐."*

## 0. 왜 필요한가 — 지금은 비대칭이다

| | Claude → Codex | Codex → Claude |
|---|---|---|
| 주소 지정 | `<@messi agent audit>` 멘션 **필수**(없으면 무음 소실) | 규약 없음 |
| 태그 어휘 | `[APPLY]`/`[PLAN]`/`[REVISE]`/`[DISCUSS]`/`[STOP]`/`[RESET]` | **없음 — 자유 서술** |
| 접수 확인 | `SLACK → AGENT` 로그 | **없음** |
| 긴급도 판별 | 태그로 기계 판별 가능 | **불가능** |

**Codex → Claude 가 자유 서술이라 "완료인지, 막힌 건지, 묻는 건지"를 기계가 구분할 수 없다.**
그래서 "코덱스가 난리칠 때 바로 대응"이 구조적으로 불가능했다. 이 문서가 그걸 없앤다.

## 1. 공통 봉투 — 양방향 동일

```
<@수신자> [TAG] 발신자 — 한 줄 제목

본문
```

- **수신자 멘션은 양방향 필수.** Claude → Codex 는 이게 없으면 Socket Mode 가 이벤트를 안 준다
  (2026-09-04 실측 확정, `CODEX_OPERATING_RULES.md` 참조). Codex → Claude 는 감시기가 라우팅하는 근거다.
- **태그는 멘션 바로 뒤, 대괄호, 맨 앞.** 백틱으로 감싸지 마라 — 백틱 때문에 승인이 죽은 전례가 있다.
- 발신자 표기: Claude 는 `🤖 Claude Code`, Codex 는 `🔧 Codex`.

수신자 ID: Codex `<@U0BUNS24998|messi agent audit>` · Claude `<@U0BUNP1R95Y|Claude>`

## 2. 태그 어휘

### Claude → Codex (지시) — 기존 유지
| 태그 | 뜻 | 실행 |
|---|---|---|
| `[PLAN]` | 계획 공유 | 안 함 |
| `[APPLY]` | 실행하라 | 함 |
| `[REVISE]` | 재작업하라 | 함 |
| `[DISCUSS]` | 정책·규칙 전달 | 안 함 |
| `[STOP]` | 중단 | — |
| `[RESET]` | 상태 초기화 | — |

### Codex → Claude (보고) — **신설**
| 태그 | 뜻 | 감시기 처리 |
|---|---|---|
| `[DONE]` | 완료. §3 증거 필수 | 일반 — Claude 검수 대기열 |
| `[FAIL]` | 테스트·빌드 실패 | **즉시 에스컬레이션** |
| `[BLOCKED]` | 막힘. 무엇이 막았는지 필수 | **즉시 에스컬레이션** |
| `[ASK]` | 질문·판단 요청 | **즉시 에스컬레이션** |
| `[LIMIT]` | 턴·티켓 한도 초과로 중단 | **즉시 에스컬레이션** |
| `[NOTE]` | 정보 공유, 응답 불필요 | 조용히 기록 |

**"난리칠 때"의 기계적 정의 = `[FAIL]`·`[BLOCKED]`·`[ASK]`·`[LIMIT]`.**
이 넷이 뜨면 감시기가 지연 없이 Claude 를 깨운다.

**태그 없는 Codex 메시지는 `[NOTE]` 로 간주한다.** 즉 긴급 신호를 놓치지 않으려면 코덱스가 태그를 붙여야 한다.

## 3. `[DONE]` 본문 필수 항목

AGENTS.md "Release and handoff" 를 그대로 구조화한 것이다. 하나라도 빠지면 Claude 는 검수하지 않고 반려한다.

```
commit : <SHA>
branch : <브랜치명>
push   : yes | no
tests  : <통과>/<전체>, 기준선 대비 신규 회귀 <n>건
files  : <변경 파일 수>
```

증거(diff·빌드 산출물·스크린샷·테스트 출력)는 완료 조건에 걸린 것만. "됐습니다"는 증거가 아니다.

## 4. 리액션 — 양방향 동일

| | 뜻 |
|---|---|
| 👀 | 읽음 |
| ✅ | 동의·승인·완료 확인 |
| ❓ | 질문 있음 |
| 🛑 | 중단·기각 |

발주자는 리액션을 쓰지 않기로 확정됐다. **`ginger` 계정 반응은 예외 없이 Claude 가 단 것으로 해석한다.**

## 5. 접수 확인 — 양방향 필수

- **Claude → Codex**: `SLACK → AGENT` 로그가 접수 증거. **이걸 확인하기 전엔 "보냈다"고 보고하지 않는다.**
- **Codex → Claude**: Claude 가 👀 를 다는 것이 접수 증거.
- 어느 쪽이든 **90초 안에 접수 증거가 없으면 감시기가 무음 실패로 경고**한다
  (`CODEX_ORDER_SLACK_WATCHER.md` §7).

무음 실패는 이 프로젝트의 반복 사고다 — 백틱 `RECORDED NOTHING`, `SLACK_AUDIT_REQUIRED="ture"` 오타,
멘션 누락. 전부 시끄럽게 만든다.

## 6. 스레드 규율 — 양방향 동일

- **답은 항상 원 스레드 안에.** 새 스레드 금지.
- 스레드를 닫을 땐 ✅ 또는 🛑 + **한 줄 마감 문구**. 애매하게 끝난 스레드도 "왜 더 볼 필요 없는지"를 남긴다
  — 발주자가 열어보고 "아직 처리 안 된 건가" 판단하게 만들지 않는 게 목적이다.
- 채널 구분: `#자동사냥` = 실행·보고, `#brainshower` = 트레이드오프 있는 설계 판단. 섞지 않는다.

## 7. 권한 경계 (변경 없음, 확인용)

- `[APPLY]` 는 **이미 승인된 지시서**에 대해서만 Claude 가 보낼 수 있다.
- `[REVISE]` 는 발주자 전용. 예외는 3D 검수 자율 루프 안에서만(`CODEX_3D_VISUAL_QA_PROTOCOL.md` §6).
- push · merge · 배포는 언제나 발주자 승인 사안.
- 감시기는 절대 자동 응답하지 않는다. 깨우는 데까지다.

코덱스가 2라운드 두 응답 모두 **확정안 3건 전부 동의**. 아래가 최종본이다.

## A. ID 기반 중복 제거 — 태그보다 이게 핵심이다

코덱스 지적으로 **내 초안을 폐기했다.** 초안의 dedup 키 "지시서 경로 + 발행 시각"은
**재발송마다 시각이 달라져 중복을 못 잡는다.** 오늘 B를 두 번 보낸 게 정확히 그 반례다.

- 발행자가 **고정 `instruction_id`** 를 부여하고 재발송 시 **재사용**한다.
- 수정 지시는 **새 ID + `supersedes: <이전 ID>`** 를 명시한다.
- 보조 dedup 키로 정규화한 지시 본문의 해시를 쓴다.
- 실행 중이거나 완료된 동일 ID는 **실행하지 않고 `[NOTE]` 로 현재 상태를 회신**한다.
- 모든 회신에 **`instruction_id` + `reply_to_message_ts`** 필수. 한 스레드에 여러 작업·질문이
  교차해도 무엇에 대한 응답인지 기계적으로 판별된다.

## B. 상태 전이 — 늦게 도착한 메시지가 뒤 상태를 덮지 못하게

```
queued → running → waiting → terminal
```
- terminal 이후의 재실행은 **새 `instruction_id` 로만** 허용한다.
- 늦게 도착한 `[DONE]` 이 이후의 `[FAIL]` 을 덮어쓰는 것을 금지한다.

## C. TTL = 4시간 (확정)

- **수신 시점 기준 4시간.** 초과 지시는 실행하지 않고 `[ASK]` 로 재승인을 요구한다.
- **이미 실행이 시작된 작업에는 TTL 을 적용하지 않는다.**
- 근거: TTL 오탐 비용이 만료 미탐지보다 크다. 코덱스 작업 단위가 수십 분이고 발주자 부재는
  보통 2시간을 넘는다. 2시간이면 정상 지시가 반려돼 `[ASK]` 왕복이 늘고 그게 턴 예산을 먹는다.

## D. `[DONE]` 은 전체 완료 전용 (초안 폐기)

내 초안의 `[DONE] scope: 3/5` 는 **기계적으로 모순**이라는 코덱스 지적을 받아들였다.

- `[DONE]` — **승인된 범위 전체**가 충족된 경우에만.
- 진행 중 보고 — `[NOTE]`
- 더 진행 불가 — 원인에 따라 `[BLOCKED]` · `[FAIL]` · `[LIMIT]`,
  본문에 **`완료 n/m · 미완: <항목>`** 을 필수 필드로 넣는다.

## E. `[ASK]` 의 턴 회계

- `[ASK]` 는 **현재 턴을 종료·반납**하고, 답변이 오면 **새 턴으로 재개**한다. 대기로 예산을 태우지 않는다.
- 재개 정보는 `thread_ts` 만으론 부족하다. **원자적으로** 저장할 것:
  `instruction_id` · 질문 ID · 현재 단계 · 완료 항목 · 남은 예산 · 계약/브랜치 기준점.

## F. 증거 분량 — 본문 총 20줄 이하 (확정)

코덱스가 문구 모호성을 지적했고 그게 옳다. **"상한과 무관하게 본문 필수"는 상한을 무력화한다.**
확정 문구는 이것이다:

> **본문은 총 20줄 이하이며, 실패 시 `실패 명령` · `종료코드` · `최초 원인 줄` 세 가지를 그 20줄 안에 반드시 포함한다.**

전문은 붙여넣지 말고 산출물 경로로 연결한다. 경로에 접근 못 하는 수신자를 위해 위 3줄은 본문에 남는다.
(예전에 테스트 출력 전문을 올려 Slack 27개로 쪼개진 전례가 있다.)

## G. 샌드박스 경계 — 오늘 실제로 터진 사고

B(`[APPLY]` 캐시 예열)가 `AgentLoopError: codex workspace-write turn produced no file changes` 로 죽었다.
코덱스 잘못이 아니라 **발행 잘못**이다 — 지시서를 `messi-specs/`(저장소 바깥)로 가리켰고,
대상 `api_server/main.py` 는 저장소 루트라 `--cd messi-2-dashboard` 샌드박스 밖이었다.

- **`agent_loop.py` 의 PROJECT_ROOT 는 넓히지 않는다.** 샌드박스 축소는 의도적 방어선이다
  (ETL 로 데이터 10,464행 소실 전례). 프론트 전용 루프에 백엔드 쓰기 권한을 주지 않는다.
- **지시서는 PROJECT_ROOT 안에 복사본**을 두고 그 경로로만 가리킨다.
- **발행 전 샌드박스 검사** — 지시서 경로와 명시된 작업 대상을 정규화해 전부 샌드박스 안인지 확인하고,
  하나라도 밖이면 Slack 디스패치를 **거부**하고 발행자에게 알린다. 밖이면 저장소 루트를 cwd 로 하는
  직접 `codex exec` 경로로 보낸다.
- 같은 검사에서 **대상 워크트리의 미커밋 변경 파일을 전부 확인해 경고**한다. 기존 작업을 의도적으로
  이어가는 경우가 있으므로 이것만으로 디스패치를 막지 않는다. 청결 확인 자체가 실패해도 경고하고 계속한다.
- 이 검사가 있었으면 오늘 B 는 **실행 턴을 쓰기 전에** 걸렸다.

## H. 발행 권한과 승인의 결속

- 실행 메시지에 **승인자 · 승인 시각 · 승인 대상 `instruction_id`** 를 포함한다.
- **본문을 수정하거나 대체 지시를 내면 기존 승인이 자동 승계되지 않는다.**
